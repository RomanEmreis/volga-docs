Raw Request Body

Most handlers take a typed extractor — Json<T>, Form<T>, Multipart — and never touch the bytes underneath. When you do need them (a proxy, a webhook whose signature covers the exact payload, a custom wire format), Volga exposes the body itself.

Reading the Body as Bytes

Starting with v0.9.4, HttpBody is an extractor — take it as a handler argument to get the raw request body:

[dependencies]
volga = { version = "..." }
tokio = { version = "...", features = ["full"] }
http-body-util = "0.1"

use http_body_util::BodyExt;
use volga::{App, HttpBody, ok};

#[tokio::main]
async fn main() -> std::io::Result<()> {
    let mut app = App::new();

    app.map_post("/raw", |body: HttpBody| async move {
        let bytes = body.collect().await?.to_bytes();
        ok!(format!("received {} bytes", bytes.len()))
    });

    app.run().await
}

Collecting the body needs the Body trait methods, which come from the BodyExt extension trait of http-body-util — Volga does not re-export it.

Warning

The request body is a stream that can be consumed only once, so HttpBody cannot be combined with another body extractor in the same handler. Extractors that read only the request head — Path<T>, Query<T>, HttpHeaders, Dc<T> — combine with it freely.

Tips

The body limit still applies: by default Volga rejects request bodies over 5 MB. Configure it with with_body_limit() or lift it entirely with without_body_limit().

Passing the Body Through

HttpBody can also be returned, which makes a pass-through handler a matter of moving it into the response — nothing is buffered:

use volga::{App, HttpBody, HttpResponse, headers::ContentType};

#[tokio::main]
async fn main() -> std::io::Result<()> {
    let mut app = App::new();

    app.map_post("/trace", |body: HttpBody| async move {
        HttpResponse::builder()
            .status(200)
            .header(ContentType::multipart_form_data("X-BOUNDARY"))
            .body(body)
    });

    app.run().await
}

Streaming the Body

To process the body as it arrives instead of collecting it, take HttpBodyStream — a ByteStream over the request body, which implements Stream<Item = Result<Bytes, Error>>:

[dependencies]
volga = { version = "..." }
tokio = { version = "...", features = ["full"] }
futures-util = "0.3"

use futures_util::StreamExt;
use volga::{App, http::HttpBodyStream, ok};

#[tokio::main]
async fn main() -> std::io::Result<()> {
    let mut app = App::new();

    app.map_post("/count", |mut stream: HttpBodyStream| async move {
        let mut total = 0;
        while let Some(chunk) = stream.next().await {
            total += chunk?.len();
        }
        ok!(format!("received {total} bytes"))
    });

    app.run().await
}

Use this for bodies you would rather not hold in memory at once — hashing an upload, forwarding chunks to storage, parsing a line-delimited stream.

Building a Body

The same type constructs response bodies, which is what the ok! family of macros does under the hood:

ConstructorProduces
HttpBody::fulla complete in-memory body from anything convertible into Bytes
HttpBody::emptyan empty body
HttpBody::json / forma serialized JSON or form body
HttpBody::filea streaming body over an open file
HttpBody::stream / stream_bytesa streaming body over any Stream

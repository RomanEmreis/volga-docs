Agent Skill

Готовый Agent Skill, который учит кодового ассистента писать на Volga правильно, — тот же материал, что и на этом сайте, но переупакованный под модель, а не под читателя.

Скачать volga-skill.zip~50 КиБ · MIT · для volga 0.12.0

Исходники: skill/volga.

Зачем это нужно

Ассистенты уверенно ошибаются в Volga, и причина конкретная: в ветке 0.9 поменялись умолчания безопасности и исчезло целое семейство вспомогательных методов, в 0.10.0 перестроилось то, как запросы доходят до middleware и как группы маршрутов применяют свои настройки, в 0.10.1 изменился ответ на отклонённый токен, в 0.11.0 появились синхронные обработчики, catch-all маршруты и таймаут завершения, в 0.11.1 — собственный fallback у группы маршрутов, а в 0.12.0 Err обработчика стал ошибкой для map_err, а не вторым видом ответа, — при том что почти весь код на Volga, который модель видела, написан до всего этого. Поэтому типичная ошибка — не забытое имя метода. Это ассистент, который пишет ok!("hi", [("x-key", "v")]) через запятую вместо точки с запятой, возвращает Err("not found".to_string()) и получает 500, тянется к with_default_cors(), вызывает use_cors() на приложении, где CORS не настроен, раздаёт статику через map_static_assets() или отдаёт конфигурацию bearer-аутентификации, которая за прокси с терминацией TLS отвечает 400 на каждый запрос.

Скилл выносит ровно эти ловушки вперёд, а за подробностями отправляет в нужный файл.

SKILL.md намеренно короткий: это точка входа, которую агент читает всегда, и восемь справочников, которые он подгружает только под конкретную задачу.

Установка

Формат SKILL.md — общий стандарт, поэтому установка везде одинаковая: распаковать и скопировать каталог volga/ в папку скиллов инструмента, сохранив имя каталога — оно должно совпадать с полем name во frontmatter.

ИнструментПерсональноВ проекте
Claude Code~/.claude/skills/volga/.claude/skills/volga/
opencode~/.config/opencode/skills/volga/.opencode/skills/volga/
Codex CLI~/.codex/skills/volga/.codex/skills/volga/
unzip volga-skill.zip
mkdir -p ~/.claude/skills && cp -r volga ~/.claude/skills/

После этого ассистента нужно перезапустить — скиллы обнаруживаются при старте.

opencode дополнительно читает .claude/skills/ и .agents/skills/, так что одна копия внутри проекта может обслуживать несколько инструментов.

Всё остальное

Подойдёт любой ассистент, умеющий читать файлы. Укажите ему на SKILL.md и дайте пройти по ссылкам — либо добавьте строчку в AGENTS.md проекта:

For Rust web work with the `volga` crate, read
`.agents/skills/volga/SKILL.md` and the reference file it routes you to.

Что вынесено вперёд

Смысл скилла, в отличие от пересказа документации, — именно список того, в чём модель ошибается сама по себе. Часть того, что SKILL.md ставит до всего остального:

  • Пользовательские заголовки идут после точки с запятой: ok!("Hello"; [("x-key", "v")]). Запятая попадает в ветку format! и не компилируется.
  • with_* забирает App по значению, map_* — по &mut. Сначала цепочка настроек, потом маршруты, и приложение объявляется как let mut app.
  • require_https и strip_token_from_request включены по умолчанию для bearer-аутентификации — из-за этого локально работающая конфигурация за обратным прокси отвечает 400.
  • with_aud делает aud обязательным клеймом, пока не вызван without_strict_aud().
  • with_default_cors() и with_default_tracing() удалены, а builder-методы вида with_credentials, with_preload больше не принимают bool.
  • Path<T> — это кортеж, NamedPath<T> — именованная структура, и ни тот, ни другой нельзя смешивать с позиционными параметрами пути в одном обработчике.
  • full — это не «всё»: #[derive(Claims)], #[http_header], dev-сертификаты и TestServer требуют фич, которых в full нет.
  • Отклонённый bearer-токен — это 401, а не 403 начиная с 0.10.1; 403 остался за действительным токеном, которому не хватает роли или разрешения, требуемых маршрутом.
  • Неразрешимый граф зависимостей останавливает приложение на старте начиная с 0.10.1, поэтому ручная реализация Inject должна декларировать то, что она резолвит.
  • Синхронный обработчик выполняется на воркере рантайма — блокирующая работа оборачивается в blocking, а не пишется в обычной fn.
  • Значение catch-all — не безопасный путь к файлу: {*path} приходит ненормализованным, вместе с ...
  • Бесконечные ответы завершаются по сигналу остановки через экстрактор ShutdownHandle, а не обрываются по таймауту завершения.
  • Оболочка SPA отвечает только на GET и HEAD начиная с 0.11.1, а API на том же сервере получает собственный map_fallback у своей группы.
  • Err обработчика — это ошибка начиная с 0.12.0: он доходит до map_err, голая строка отвечает 500, а тип ошибки реализует IntoError — никогда не From<T> for Error.

Код в нём компилируется

Rust-код скилла собирается против опубликованных крейтов volga в CI этого репозитория — той же задачей, что проверяет сниппеты на сайте, — так что то, что ассистент оттуда копирует, компилируется. Блоки, показывающие форму, а не программу (сигнатура, impl с опущенными телами), исключаются явно.

Ту же проверку можно запустить локально:

python3 ci/check-snippets.py --docs-dir skill --default-mode compile-fragment --default-features "full auth-full macros dev-cert test"

Версия

Скилл описывает volga 0.12.0 при MSRV 1.90. Обе величины записаны во frontmatter, чтобы ассистент мог понять, совпадает ли скилл с крейтом в проекте:

metadata:
  volga-version: "0.12.0"
  msrv: "1.90"
